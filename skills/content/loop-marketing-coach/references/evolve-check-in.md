# Evolve check-in

Run on the cadence in the brief's Evolve section, or when the user asks how a
campaign is doing.

## Steps

1. **Read the brief:** goal, target, baseline, start and end dates, metrics,
   past check-ins.
2. **Get the numbers.** Use the analytics tools available in the session
   (product analytics, revenue, search console, social analytics) filtered by
   the campaign UTM and dates where the tool supports it. Otherwise ask the user
   for the values. Record source and date for every number.
3. **Compare with pace.** Expected so far = baseline + (target gain × share of
   the time window elapsed). Report actual vs expected, not just actual. For an
   open-ended campaign, compare with the previous check-in.
4. **Find the driver.** Which posts or channels produced most of the result?
   Which hook or format won? Separate what the data shows from your
   interpretation.
5. **Decide.**

   | Situation | Decision |
   |---|---|
   | On or ahead of pace | Keep; do more of the winning format |
   | Behind pace, one clear underperformer | Change that piece (hook, format, channel) |
   | Far behind after two check-ins with changes | Revisit the offer or the audience slice (back to Express) |
   | Target reached or end date passed | Close: status `done`, write lessons |

6. **Propose the log row** for the Evolve table (date, values with source, what
   we learned, change) and write it after the user approves.
7. **Feed the loop.** When a lesson is about voice, audience or beliefs, suggest
   the matching Taste Profile edit for marketing-project-setup to apply.

## Output

Lead with the verdict (ahead, on pace, behind), then the numbers with sources,
the driver, the decision and the proposed log row. Mark simulated or estimated
values clearly; better still, leave them out.
